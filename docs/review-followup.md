# 再レビューへの対応（2026-09-11）

## 修正の理由と範囲

別名の本文処理スクリプトを追加した設定と、存在しない SHA を指定したスタブ参照が検証を通過した。設定検査は `[Script]` の全有効行を対象にし、定義名による見逃しを防ぐ。実行コードは全5参照の実在・同一コミット・作業ツリーとの一致をリリース時に確認する。CI に配布参照の検査を追加した。

DOM 保護が子孫だけを検査してフォーム自身を削除する問題は、要素自身の判定を追加して修正した。壁候補の部分一致 CSS と Funding Choices の無条件非表示も撤去し、名前・文言・保護対象を JavaScript で確認する。正常な記事、描画途中のフォーム、編集領域が可視のまま残ることを jsdom と Chromium で検査する。未分類の壁や操作部品を含む壁は残る可能性がある。

本文 pattern、MITM ホスト、リライトの対象、DNS、配布ルールの内容は拡大・変更しない。実機で `/special/` 系の壁が出ないとのユーザー報告を受け、`/special/`・`/publicity/` の本文注入は追加しない。個別 URL と端末版が記録されていないため、これを全ページでの保証にはしない。

## 文書とライセンス

現行の保守手順を CLAUDE.md、端末操作を shadowrocket_update.md に集約し、矛盾する旧記述を history 配下へ隔離した。通常更新で conf を再取得する指示と、SHA だけで構成全体を戻せるという説明を撤去した。負の MITM 項目の追加が検証で拒否される場合も含め、実装と手順を一致させる。

第三者由来部分、外部 URL 参照、テスト依存物の区別を THIRD_PARTY_NOTICES.md に記録し、単体配布ファイルへライセンス・通知への案内を追加した。今後の JP 変換は `--source-ref` に上流の完全 SHA を要求し、出典を生成物へ記録する。既存 JP リストのルールは再生成せず、通知だけを追加した。

既存の JP 入力コミット、uAssets 移植元の正確なファイル・コミット、採用時点の通知と版選択条件は未確定。現在の上流を過去の採用元と偽って記録したり、第三者部分を再許諾したりしない。これらの履歴照合は未完了として明示する。

## 検証と適用

通常テストは変更した実装を検証し、配布参照検査はその実装と固定 SHA の一致を検証する。ブラウザ E2E は合成ページでの動作確認で、CDN や Shadowrocket 実機の保証ではない。PR 本文に実際の検証結果を記載する。

コードの実装コミットを作り、その SHA に module の参照を更新する。クロスレビューと CI 成功後にユーザーがマージを判断する。端末適用は module 更新と接続 OFF/ON。復旧は前版 module 全体で行う。設定ファイルへの通知追記だけを理由に端末の conf を再取得する必要はない。

構成一式の不変スナップショット、配布リストの例外再照合、DNS 退避経路、UDP/443 全体遮断、CDN の302依存は引き続き未解決の設計課題。
