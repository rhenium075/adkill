# 敵対的レビュー後の安全性修正

本変更は 2026-09-10 のインシデントを受け、危険な設定変更をテストが見逃す点と、
実際に反例を確認した誤判定を修正する。Shadowrocket の未確定な解析限界を修正済みと
扱うものではない。根本原因の確定と実機検証は別の作業として残る。

## 実装した範囲

MITM は conf と module の合成後を検査する。両ファイルの各行と合成後について
バイト数・項目数・正負の競合を確認し、tools/mitm_policy.json にない復号パターンを拒否する。
4KB/200 項目は保守的な運用上限であり、Shadowrocket の解析限界を測定した数値ではない。
許可範囲の変更はポリシー差分もレビュー対象とし、テスト成功だけで新規ホストを採用しない。

本文処理は、HTTPS の example.com/example.org/neverssl.com/httpforever.com のルート、
平文 HTTP の neverssl.com のルート、trafficnews.jp のトップ・post/数値 ID と任意の
数値ページ・category/英小文字名だけに限定する。trafficnews のサブドメインは復号対象から
外す。会員機能・ログイン・API・画像配信・未知の文書パスは対象外になる。
公開ルートの形は https://trafficnews.jp/post/706678 と
https://trafficnews.jp/category/railway で確認したが、実機での注入成功は別途必要。
同じ URL がヘッダ等により別の形式を返す可能性まで、URL 制限だけでは排除できない。

DOM の汎用ダイアログは文言と寸法だけでは削除しない。名前と文言の一致を必須にし、
フォームや本文を保護する。iframe は error-report.com とそのサブドメインの /modal
パスに限定する。全画面・最大 z-index だけの判定、無関係なバックドロップの削除、
URL 部分一致 CSS、setTimeout の関数内容による抑止は撤去する。この結果、未分類の壁や
背景が残る可能性があるため、必要なものはサイト別の明示的な対策として追加する。

サイト審査は同一ホストの HTTPS 転送のみ許可し、転送先でも禁止対象を再判定する。
meta CSP、文字コード、圧縮失敗・検査上限を確認する。PASS は取得した一応答の観測であり、
ホスト全体やサブドメインの安全証明ではない。出力にワイルドカードを自動追加しない。

JP フィルタの変換は、後続セクションも含めたネットワーク例外と重なるドメインを
出力から除外する。条件付き例外は DNS に表現できないためドメイン単位の遮断を見送り、
解釈できない例外は生成を失敗させる。配布済み adkill_jp.list はこの PR では再生成しない。
独自/DNS/外部ルールに同じ遮断が残り得るので、リスト更新は全層の合成結果を別途確認する。

エミュレータは固定 SHA のコードを読み、CDN への302をブラウザに実行させる。
非文書が requires-body の対象になった場合など、再現できない通信条件は非ゼロ終了する。
ADKILL_JS による手元コードの指定は開発用と明示する。単体テストは手元の変更コードを検証する。

## 反映とロールバック

コード変更のコミットを作り、その完全 SHA に module の実行コード参照を進めたコミットを
続けて作る。Fable のクロスレビューと CI の確認後、ユーザーがマージと端末反映を判断する。
この PR は conf 本体、CA 秘密鍵、DNS 設定、配布中のブロックリストを変更しない。
端末への反映は module の更新と接続 OFF/ON。変更前の module を端末で復元できるよう保持する。

この PR の差分は module とコードで戻せるが、システム全体を過去の状態へ戻せるという意味ではない。
custom/jp/上流の main・master 参照は依然可変である。コードの SHA だけを戻しても、
本文 pattern や復号対象は戻らないため、この PR を戻す際は module 全体を復元する。

## マージ判断・実機確認で必要な証拠

Fable は、module に *.com / claude.ai を追加した変更が拒否されること、ポリシー自身の
変更で不用意に許可が広がっていないこと、本文対象を狭めたことによる機能の後退を確認する。
既知壁の除去が保たれ、広告ブロックについて説明する正常な UI と入力フォームが残ることも確認する。
CI の全テスト成功と、固定 SHA がこの PR の修正済み adkill.js を指すことを照合する。

端末で module の版・Shadowrocket/iOS の版を記録し、Claude・LINE・決済アプリの起動と通信、
example.com のバッジ、trafficnews のトップ/記事/次ページ、newsdig の壁・CSS、livedoor の
平文 HTTP を確認する。バッジ一つの成功を他サイトや他アプリの成功と扱わない。
不調時に前版 module へ戻して復旧することまで確認してから次の変更へ進む。
ログは共有前に認証情報・クエリ・個人情報を削除し、必要なホストとエラーだけを残す。

## 残る設計課題

構成一式の固定は未完了。次の移行ではローカル CA と小さな端末設定を保持し、module・コード・
独自/JP/外部ルールの不変スナップショットとハッシュを一つのリリースとして管理する。
取得失敗時は検証済みの前版を保ち、切替・復旧も一式で行う。現行 conf の可変参照を変えるため、
CA 保持を含む移行手順の実機確認が必要である。

スタブの302依存は残る。元 URL への直接応答置換は Shadowrocket の対応方法と実機挙動を
確認してから実装する。CDN 失敗、CSP、キャッシュを含む検証をエミュレータの描画成功だけで
代用しない。DNS の独立した退避経路と UDP/443 の全体遮断の見直しも、到達性と広告遮断の
要件を照合する別の設計変更として扱う。許可リストは「壊れない」という保証ではない。
